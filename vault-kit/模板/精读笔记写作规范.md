# 精读笔记写作规范

适用于 `template_version: 2` 的《论文精读模板.md》。目标是让读者先看懂论文解决什么、方案怎样工作、证据支持到哪里，再按需查细节。模板中的提示用于写作，成稿时删除；本规范不复制进每篇笔记。

## 1. 六问是唯一正文主线

| 导师六问的原始含义 | 新版书面表述 | 本问应交付的内容 |
| --- | --- | --- |
| 他在解决什么问题 | 研究问题与研究目标是什么？ | 场景、任务、成功标准和边界 |
| 现有方法做到了什么 | 已有研究取得了哪些进展，仍存在哪些不足？ | 最相关的已有能力与具体缺口 |
| 解决问题的挑战是什么 | 解决该问题的关键挑战及其成因是什么？ | 障碍及其技术原因 |
| 大概思路是什么 | 论文的总体思路与方法框架是什么？ | 核心思想、阶段分工与流程 |
| 具体设计；5.1 创新性 | 关键技术如何实现，创新性体现在哪些方面？ | 机制、创新比较与设计权衡 |
| 实验批判 | 实验与论证能否充分支持论文结论？ | 设置、结果、证据强度与边界 |

创新分析属于第五问，不再额外编号为第六项。第六问兼容实验和其他论证方式，不预设论文一定存在错误。

- 每问开头先给直接回答，再展开。避免以背景史、缩写串或泛泛评价开头。
- 第四问解释整体结构，第五问解释内部机制，第六问检验证据。一个机制只完整写一次，其他位置回指。
- 不再在六问之后平行复制研究对象、研究方法、技术机制、数据来源和研究结论。
- 篇幅按解释任务分配：总览约100–150字；第一至四问保持简短；篇幅主要用于第五、六问。核心正文通常约2000–3500中文字，证据摘录不计；这是压缩参考，不是硬上限或凑字数目标。
- 每段回答一个问题，通常2–4句；列表嵌套尽量不超过一层。表格用于可比较的信息，长机制用短段落说明。
- 优先删重复、生态清单、无关背景和空泛评价，不删重要前提、反例、证据边界或尚未解决的疑问。

## 2. 先还原架构，再组织细节

- 系统或方法论文：给出输入、主要阶段、输出，以及各阶段的数据或状态变化。清楚区分离线准备与在线处理；确有必要时再区分控制流程与数据流。
- 流程通常3–6个节点，可用文本箭头或简洁 Mermaid 图。每个节点都应对应原文中可定位的机制；本笔记重绘必须注明，不凭空补模块或连接关系。
- 原文架构图能显著帮助理解时，引用已有全文中的实际图片并标注图号、PDF页码和中文说明。不要为装饰加入图片。
- 使用同一个小例子贯穿第四、五问，减少读者反复切换语境。教学例子必须标注“本笔记示例，非论文实验”，不得用自造输出证明论文有效。
- 技术点按论文实际选取，通常1–3项。每项讲清“对应挑战、如何运作、为何有效、付出什么代价”，不强行拆成三个贡献。
- 公式只保留理解主线必需的部分，紧邻解释变量、含义、前提和用途。无法可靠还原的公式不猜写，登记原文位置与待核对项。

### 将有用原图融入对应论证

图片是正文证据与解释的一部分，不是附件陈列。论文中凡是能显著降低理解成本，或直接支撑关键结论的原图，应放在它所解释的句子、技术点或发现附近；笔记中不得另设“论文图片”“图表汇总”或类似章节。

- **选择真正有用的图**：优先保留问题对比图、总体架构或工作流、关键机制图、核心结果图、消融／敏感性／错误分析图。若界面交互本身是贡献，可保留界面图。删除装饰图、机构标志、作者照片、内容重复的图，以及只因“论文里有”而加入的图片。
- **覆盖论文主线，而非追求数量**：没有固定图数。一张图能解释清楚就不重复放；复杂论文可以使用多张。正文提到某张关键图时，应实际嵌入或明确说明未嵌入原因，不能只留下 “见 Figure N”。
- **就地放置**：问题或失败图放第一至三问；总体架构与流程图放第四问；组件、算法和设计权衡图放第五问对应技术点；结果、消融与误差图放第六问对应 F 条目附近。同一图片通常只出现一次，其他位置用图号回指。
- **图不另起小节**：图片直接跟在它解释的挑战、阶段、技术点或 F 编号之后，以图题和三项中文说明继续当前论证；不使用“对应原图”“结果图汇总”等过渡标题把图片从正文拆开。
- **使用可追溯的原图**：优先引用 `03fulltext/<collection>/images/<zotero_key>/` 中已经存在的论文原图，并核对文件确实对应所写图号。图片提取缺失时，使用原 PDF 或用户提供的高清页图补取，归档到同一图片目录并记录来源；不得把本笔记重绘图冒充论文原图。
- **每图必须有中文解释**：图下依次写图题与 PDF 物理页、读图顺序、它支撑的具体问题／技术点／F 编号，以及证据边界。读图说明先解释模块、箭头、坐标轴、单位、图例和子图，再提炼结论，让读者不读英文图注也能理解。
- **区分看见与推断**：只写图中可辨认的信息和论文正文给出的解释。低清图中的柱高或曲线值只能标“估读”；精确数值优先取表格或正文。缺柱、截断坐标、对数轴、误差线、样本量、均值／中位数／分布口径都要就地说明，不能跨图表混用。
- **图文必须互相校验**：正文主张应与图中趋势一致。图展示相关性时不要写成因果；架构图只能证明作者设计了这些模块，不能单独证明系统有效；定性示意图不能替代实验数据。
- **保证可读性**：优先使用清晰裁图；多子图可并排嵌入，并按 (a)、(b) 顺序解释。图中文字过小则换高清图或拆分子图，不要求读者放大整页 PDF 才能看懂。图片链接必须可在 Vault 内解析。

## 3. 术语备注适量、就地、中文优先

**选择标准**：不理解该词就无法理解当前机制或结论时才补注。一般首次出现解释一次；后文只在含义发生变化时再次说明。不必每问都有备注。

- 通常6–12条足以支撑一篇笔记，短文可更少，复杂论文可更多；没有最低配额，也不追求英文引文比例。
- 每条通常1–2句、约40–90个中文字：先说“是什么”，再说“在这里做什么”。必要时给一个小例子或区分一个易混概念。
- 用中文解释，英文只保留首次识别所需的原名、缩写、符号或代码。不得用一段英文定义代替中文解释，不在备注里堆长引文。
- 一条只解释一个概念或紧密关联的一组概念，避免为了说明一个词再引入多个生词。已有准确中文术语时优先使用。
- 论文特有定义或机制的中文释义附PDF物理页；一般背景明确标注“补充背景，非论文原文”。例子、近似理解与作者定义要分清，不能用通俗化牺牲准确性。
- 备注只帮助理解。创新评价、证据批判、研究设想分别放第五问、第六问与“我的判断与研究启发”。

统一格式如下，占位内容必须在写作时替换：

```markdown
> 📌 **术语｜中文名（必要时附原名或缩写）**：用中文解释概念及其在本文的作用。（论文释义；论文表述见 PDF 第 N 页）

> 📌 **术语｜中文名**：用中文解释一般知识，必要时加一个短例子。（补充背景，非论文原文）
```

合适的背景备注示例：

> 📌 **术语｜消融实验**：从完整方法中去掉或替换某个组件，再比较结果，用来判断该组件是否带来收益。解释结果时仍需留意组件之间的相互影响。（补充背景，非论文原文）

保留模板中的单次图例。每条备注单独占一个物理行，前后留空行；优先放在普通段落后，使用零缩进，避免打断列表编号。连续出现多条时，先检查是否能把必要解释写进正文或删去无关概念。全文确实无需备注时可以删除图例。

中文释义不使用 `（论文定义：“中文释义”）` 冒充逐字原句。必须保留精确定义时，备注写中文释义和定位，文末证据区另存实际英文原句。不要给中文释义加上暗示“原文如此”的引号。

## 4. 所有论文判断都能追溯到证据

每个关键主张应能回答：**谁提出、在哪个场景、用什么材料支持、能支持到什么程度**。

| 内容类别 | 推荐表述 | 不应写成 |
| --- | --- | --- |
| 作者报告的结果 | 在某数据与设置下，作者报告某指标达到某值 | 不带条件的全面优于其他方法 |
| 作者的架构或愿景主张 | 作者提出／主张；目前提供何种实现或论证 | 已经证明普遍有效 |
| 本笔记归纳与推断 | 本笔记归纳／判断；依据是什么，仍缺什么 | 论文原话或已证实的因果关系 |
| 一般背景 | 补充背景，非论文原文 | 论文的创新或作者的定义 |
| 未找到依据 | 论文未报告／未在当前材料中定位到 | 自行补出机制、参数、数字或页码 |

- “最早”“首次”“唯一”须区分作者自述与独立核验；只读一篇的相关工作不足以确认全领域首创。
- 区分论文主动声明不处理的范围、论文未提供的证据，以及本笔记提出的可能风险。未报告不等于未实现，更不等于机制必然失效。
- 主要结果贴着条件写，至少保留比较对象、指标单位及最关键的设置。模拟实验、样本极小或资源配置不等时，限制条件与醒目的倍率一同出现。
- 区分均值与中位数、百分点与相对百分比、局部性能与端到端性能、模拟调用与真实模型调用。自行计算写出来源、算式和舍入口径；图上估读明确写“估读”，不伪装成精确表值。
- 将“证据性质”与“可信程度”分开：有实验不自动等于证据强；有原句只能证明作者这样写过。强、中、弱的判断要给简短理由，不只贴标签。
- 英文原句集中保存在“原文证据与核验记录”，每条先给中文释义，再给短引文。正文用页码、图表号和E编号定位；不为每个普通术语配一段英文。
- 引文按原文抄录，保留否定、条件和不确定性。禁止从中文总结生成英文引文。省略用 `…`；连字归一化、跨页或缺文本层的取证继续遵循工作区原有纪律。
- 图表本身可以支持数值发现，不强求用正文句子重复证明图表。没有可核验原句时如实说明，保留实际的图表与页码定位。

## 5. 根据论文类型调整证据要求

| 论文类型 | 第五问重点 | 第六问重点 |
| --- | --- | --- |
| 系统／方法 | 机制、组件分工、设计权衡 | 数据与任务、基线公平性、消融、成本和复现条件 |
| 理论 | 定义、假设、定理关系、证明关键思路 | 证明支持的范围、必要前提、紧致性或反例；不强求实验 |
| 实证 | 研究设计、分析单位、变量与识别方式 | 抽样、测量误差、混杂因素、不确定性；不把相关当因果 |
| 立场／愿景 | 新视角、设计原则、论证链条 | 前提与反例、案例代表性、哪些主张尚未验证 |
| 演示 | 已展示的流程、交互和实现边界 | 功能展示支持什么，是否提供效果、成本或规模验证 |
| 综述 | 分类框架、组织方式、综合所得 | 检索与纳入范围、覆盖偏差、分类依据和争议呈现 |

混合论文可组合使用。仍保留六问；非实验论文在第六问说明一次实际论证方式后，可删除不适用的表格行，改用证明假设、案例来源或综述纳入标准，避免反复填“不适用”。应当提供却未报告的信息仍须明确记录，不能用删行掩盖证据缺口。对不同体裁使用相称的证据标准。

## 6. 将阅读变成可复用的研究材料

- 阅读顺序可按“摘要与结论 → 关键图表 → 方法与实验 → 相关工作 → 回写六问”安排。先定位证据再下判断，最后写阅读总览。
- 对已有知识不必反复铺陈；把新的机制、与近邻论文的实质差异、仍无法解释的结果留下来。
- 关联笔记只链接真实文件，并说明是替代方案、上下游、方法继承、补充证据还是条件不同。比较双方都需要笔记依据。
- 每篇优先提出一个值得验证的问题和一个最小行动。给出对照、指标及可证伪条件，避免只写“优化性能”“结合LLM”等泛泛方向。
- 只使用用户已确认的研究目标。当前方向不明时写“待确认”，不得把读过某主题自动当成用户选题。
- 保留尚未理解的点及原文位置。允许笔记处于精读中，不为看起来完整而消除不确定性。

## 7. 成稿检查与版本兼容

完成前逐项检查：

- [ ] 只看总览和第四问，能准确复述问题、方案流程与证据边界。
- [ ] 六问恰好六项，创新性放第五问；没有再用平行章节重复同一机制。
- [ ] 第五问讲清输入、处理、输出和代价，公式、流程节点能回原文定位。
- [ ] 主要结果有条件、单位、比较对象与图表或页码；作者主张、实验结果和个人推断明确区分。
- [ ] 中文术语备注短而必要，不依赖长英文引文，不循环引入生词；无备注数量或英文占比压力。
- [ ] 关键证据可核验，中文释义没有冒充逐字引文；核验状态如实记录。
- [ ] “未报告”“不适用”“待核验”使用准确；没有把单篇缺口升级为领域空白。
- [ ] 关联链接、Zotero入口、全文路径与稳定身份正确；占位符和写作提示已删除。
- [ ] 阅读阶段如实记录；未解决的问题保留在待核对项中。

版本与登记约定：

- 新写笔记使用 `template_version: 2`；没有版本字段的历史笔记按v1校验。仅在用户指定重构某篇时迁移该篇，不批量套写11篇旧笔记。
- 模板结构和本规范用于v2写作。旧版六问的口语化标题、25–35条密度目标、提高英文备注占比的目标，不用于v2质量评价。
- 保留原有机器字段。更新笔记时保留 `created`、`zotero_key`、`pdf_key`、实际路径与已核验证据；不要只改版本号却保留旧正文结构。
- 中文释义附页码的备注由既有计数器归为G，一般背景无页码归为B；M只统计可定位的逐字英文引文。M/N不是阅读质量分数，不为了提高它回填英文备注。
- 实际创建或更新笔记后，仍按既有工具复算N/M/G/B、同步登记、追加日志并运行全部审计；不能用新模板绕过引文验证或历史已知例外。本次只更新模板时，不重新登记历史笔记的数字。
